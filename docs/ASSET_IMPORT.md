## General rules


1. **Prefer glTF/glb over FBX/OBJ.** three.js consumes `GLTFLoader` natively and losslessly. `FBXLoader` works but is heavy, pulls in extra deps (fflate), and the FBX variants here carry the same content — there is no reason to use them in-browser. OBJ suffers the same: `OBJLoader` + `MTLLoader` is fine but redundant when glTF exists.
2. **glTF external dependencies must travel together.** These exports are *split* glTF (JSON `.gltf` + `.bin` buffer + external PNG textures). If you copy `X.gltf` you **must** copy its sibling `X.bin` **and every texture referenced by URI**, preserving relative paths — otherwise the loader throws `Failed to load buffer` / `404 texture`. Option B (recommended for shipping): load the `.gltf` once in a build/import step and re-export as single-file `.glb` (embedded buffers + textures) via `gltf-transform` or `gltf-pipeline`; then only one file per asset needs to reach the browser. The Universal Animation Library already ships ready-made single-file `.glb`s — use those as-is.
3. **Godot-oriented exports**: the `glTF (Godot)` / `glTF (Godot-Unreal)` folders are tuned for Godot (up-axis, scale). three.js may need a scale/rotation tweak per kit — normalize one reference asset, then apply the same transform uniformly.
4. Serve with correct MIME handling: `.glb`/`.gltf` → `model/gltf-binary` / `model/gltf+json`; `.bin` → `application/octet-stream`; `.ktx2` would need `KHR_texture_basis` support in the loader (none present in this library).
5. Keep filenames verbatim when copying (they contain only safe characters, but folder names contain spaces + brackets — always quote paths in shell commands).
